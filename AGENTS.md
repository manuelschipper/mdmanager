# Agent instructions

## Keep the changelog current

Update [CHANGELOG.md](CHANGELOG.md) in the same change whenever you make a material
user-visible change: runtime discovery, instruction composition or deployment,
CLI or TUI behavior, or a documented workflow or limitation.

- Collect changes under `## Unreleased` at the top, with the newest release first.
  When cutting a release, rename that heading to
  `## mdmanager X.Y.Z — Mon D, YYYY`, using the version in `Cargo.toml`.
- Write one bullet per change: a **bold label** naming it, followed by a plain
  description of what changed and why a user would care. Use a technical voice.
- Internal refactors, trivial copy edits, and cosmetic cleanup need no entry
  unless they change observable behavior or performance.
- Keep entries for shipped releases unchanged.

## Contributor search map

Use these canonical domain terms when naming and searching. Start at the owner below;
[CLI dispatch](src/cli.rs) and [TUI App](src/tui/app.rs) wire them into the product.

| Concept | Owner and contract |
| --- | --- |
| Sections, Profiles, Targets | [section.rs](src/section.rs) owns `Section`, ID/path validation and `render_format_1`. [config.rs](src/config.rs) owns the Global catalog: Profiles order Section IDs for each Target. [deploy.rs](src/deploy.rs) owns Global target inspection, apply and deployment state. |
| Project / Workspace | [project.rs](src/project.rs): `Workspace` loads the repository's Project manifest and Section contents; `TargetView` carries the reviewed output. `PROJECT_TARGETS` and `target_filename` own root filename policy. |
| Local / recovery | [local.rs](src/local.rs): `LocalRepository` owns machine-local compositions, disable/apply/restore, exclusion review and ownership. `RawState` is serialized data; conversion to `State` validates recovery relationships before mutation. [claude_settings.rs](src/local/claude_settings.rs) owns text-preserving Claude exclusion edits. |
| Context / Audit | [context.rs](src/context.rs): `Audit` describes one runtime's observed load chain, not a managed composition or a code review. `ContextRuntime` differs from Local's `DisableRuntime`. `PI_INSTRUCTION_CANDIDATES` owns Pi selection order; [git_worktree.rs](src/git_worktree.rs) owns shared main-worktree discovery. |
| Scan completion | [context_ui.rs](src/tui/context_ui.rs): `ContextUi` owns the scan receiver and `ContextScanStatus`; reload/runtime switches discard old receivers. App accepts completion and refreshes inspection. |
| Reload / snapshots | [reload.rs](src/tui/reload.rs) watches signatures; App sequences refresh. [inspection.rs](src/tui/inspection.rs) owns `InstructionInspection`, a refresh generation of observations, not an atomic filesystem snapshot. Pages consume accepted observations. |
| Browsing / document navigation | [library_view.rs](src/tui/library_view.rs) browses both Personal and Project Sections and Global Profiles; [managed_view.rs](src/tui/managed_view.rs), [context_view.rs](src/tui/context_view.rs) and [overview.rs](src/tui/overview.rs) own their pages. [document.rs](src/tui/document.rs) owns wrapping, search, line jumps and scroll state; App owns view history. |
| Atomic writes / ownership hashes | [config.rs](src/config.rs): `atomic_write` replaces, `atomic_create` refuses clobbering, and `sha256_hex` defines persisted ownership hashes. Scope owners validate authority and reviewed inputs before calling these primitives. |

For runtime discovery limitations, read the relevant [Claude](docs/claude.md),
[Codex](docs/codex.md), [Cursor](docs/cursor.md), or [Pi](docs/pi.md) guide.
For disable/restore support read [command recipes](docs/start.md#command-recipes); for reload boundaries and
theme behavior read [TUI](docs/tui.md). [DESIGN.md](DESIGN.md) describes module composition.

## Verification and data boundaries

Behavioral Rust tests are colocated in each owner's `mod tests`; App tests cover
cross-page navigation and refresh. [tests/cli.rs](tests/cli.rs) exercises the executable,
including read-only inspection, reviewed writes and recovery. Search test names with the
same feature terms as production. Keep prose in its product owner; assert behavior,
dynamic identities, output structure and actual byte contracts. Bundled docs are embedded
by [src/docs.rs](src/docs.rs); compare topic output with the owning Markdown source.

Build output stays under one profile. Never set `CARGO_PROFILE_*` or
`CARGO_INCREMENTAL` environment variables and do not pass `--release`: every
distinct profile value makes Cargo link a second full copy of every test
binary under `target/`, and each sddr worktree carries its own `target/`.

`Cargo.lock` is generated by Cargo. `tests/fixtures/`, SVG and binary assets are data;
`target/` is generated build output. Maintained Rust and documentation remain searchable
source, including inline tests and embedded guides.
